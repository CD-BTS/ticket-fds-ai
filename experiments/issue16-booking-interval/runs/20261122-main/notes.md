- 본 수집. 같은 e2e DB 에서 직전에 파이프라인 점검용 파일럿(`runs/pilot-01`, 계정 `pilot-*`, 예매 7건)을 먼저 돌렸다. 계정이 달라 간격에는 섞이지 않지만, 공연 0번 좌석 7석과 `card_reuse_count`·`ip_booking_density`(같은 카드·IP 를 쓴 계정 수)에는 포함된다.
- 수집 중 사람이 개입하지 않았고, 브라우저 창은 #14 README 의 명령과 같이 띄운 상태(headed)로 실행했다. #14 실제 수집 때 창을 띄웠는지는 기록이 없어 README 명령 기준으로 맞췄다.
- 관찰: Jitter·Human-like 에서 결제 단계는 코드상 기대만큼 줄었지만, 카드 UI 와 무관한 "로그인~예매하기 클릭 전" 구간과 "브라우저 종료·재기동" 구간이 각각 0.3~0.5초 늘었다. 그래서 Jitter 의 간격은 결제 단계 감소(약 1.6초)보다 훨씬 적게(약 0.56초) 줄었다. 늘어난 원인(반복 실행 방식, PC 상태, 백엔드 버전 중 무엇인지)은 이번 데이터로 가릴 수 없다.
- Fast 는 원래 카드번호를 지연 없이 한 번에 채웠기 때문에 결제 단계 변화가 거의 없다. Fast 의 평균이 1.34초 줄어든 것은 #14 의 긴 간격(38.2초) 1개가 이번에는 없었기 때문이며, 중앙값은 오히려 0.14초 늘었다.
