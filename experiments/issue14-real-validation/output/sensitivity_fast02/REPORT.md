# Fast 매크로 누적 예매 실험: Feature 민감도 분석

- 대상: `macro-fast-02` (스냅샷 `count__macro-fast-02__n03` / `n10` / `n20`), 비교군 `macro-jitter-01`, `macro-human-01` (각 20회)
- 스크립트: `scripts/sensitivity_fast_macro.py` (기존 모델·점수 계산을 읽어서 쓰기만 함)
- 모든 점수는 `card_reuse_count=1`, `ip_booking_density=1` 로 고정한 값이다 (로컬 환경 왜곡 통제).
- 판정 기준은 바꾸지 않았다. 참고선으로 모델 자체 판정 경계(정규화 점수 0.801)를 쓴다.

이 문서는 **관측 결과**(실제 수집된 이벤트에서 계산된 값)와 **가상 입력 결과**(Feature 값을 바꿔 넣어 본 값)를 구분해서 적는다.
이번 실험 한정의 오프라인 분석이며, 계정 1개·실행 1회·다시 학습한 모델 사본을 사용했다.

## 요약

1. **3 → 10 → 20회의 점수 상승(0.680 → 0.888 → 0.920)은 거의 전부 `booking_count` 증가로 설명된다.** 3→20회 변화 +0.240 중 `booking_count` 몫이 +0.214, 평균 간격 +0.026, 분산 0 이다 (가상 교체, 순서 평균).
2. **다만 점수가 모델 판정 경계(0.801)를 넘은 것은 38초짜리 긴 간격 하나 때문이다.** 이 간격을 일반적인 fast 간격으로 바꾸면 20회 시점 점수가 0.920 → 0.746 으로 내려가 경계 아래가 된다 (가상).
3. **그 긴 간격은 매크로의 행동이 아니라 브라우저 기동 지연이다.** 38.2초 중 28.7초가 기동 시간으로 기록되어 있다 (`macro_gap_breakdown__macro-fast-02.csv`, 관측).
4. **긴 간격을 뺀 fast 20회(0.746)는 jitter 20회(0.746), human 모드 20회(0.748)와 같은 점수다.** 현재 모델은 실행 모드를 구분하지 못한다.
5. **모델은 "규칙적인 간격"에 반대 방향으로 반응한다.** 분산이 작을수록(더 규칙적일수록) 점수가 낮고, 더미 정상 범위를 넘는 큰 분산에서 점수가 높다 (가상).

## 3. 해석

### 점수 상승의 구성

두 가지가 겹쳐 있다.

- **스냅샷 사이의 상승**: `booking_count` 가 3 → 20 으로 늘면서 더미 정상 범위(1~13)를 벗어난 효과다.
- **전체 수준**: 세 스냅샷 모두 긴 간격 때문에 분산이 포화 구간에 있어, 그렇지 않았을 때보다 0.12~0.20 높다.

`booking_count` 만으로는 20회에서 0.746 까지 오르고, 긴 간격이 만든 분산이 더해져 0.920 이 되었다.

### 기존 모델이 민감한 패턴

- **예매 시도 수가 많음** (8회 이상부터 뚜렷)
- **간격 분산이 더미 정상 상한(약 50)에 가깝거나 넘음**
- **카드·IP 공유 수** (이번 분석에서는 1로 고정. 실제 값 4로는 3회 계정도 0.92~0.95)

### 기존 모델이 둔감한 패턴

- **평균 간격**: 0.1~60초 범위에서 점수 차이가 0.02 이내다.
- **간격의 규칙성**: 분산이 작을수록 점수가 내려간다.
- **실행 모드**: fast(대체 후 0.746), jitter(0.746), human 모드(0.748)가 같다.

### 현재 실험에서 드러난 매크로 탐지의 한계

1. **이번 fast 매크로의 "이상" 판정은 우연한 기동 지연에 의존했다.** 지연이 없었다면 20회를 반복해도 모델 자체 판정으로는 정상이다.
2. **실제 매크로의 간격이 더미 매크로와 다른 구간에 있다.** 더미 매크로는 평균 0.1~1.3초·분산 0.5 이하인데, 실측 fast 는 5.8초다. 브라우저 재기동과 결제 지연(1.2초)이 포함되어 5초 아래로 내려가기 어렵다.
3. **횟수가 적으면 사람과 구분되지 않는다.** 3회 계정은 사람과 매크로가 모두 0.54~0.57 이다. 구분은 사실상 누적 횟수에서만 생긴다.
4. **속도를 사람처럼 늦춘 매크로를 구분할 근거가 없다.** 모드 간 차이는 시도 내부 단계 시간에 있는데, 현재 6개 Feature 에는 시도 내부 시간이 없다.

## 4. 이 분석의 한계

- 계정 1개, 실행 1회의 결과다. 다른 실행에서 긴 간격이 없거나 여러 번 생기면 관측 점수가 달라진다.
- A 의 민감도는 fast 20회 기준점 주변의 값이다. 기준점의 분산이 이미 포화 구간이라, 다른 기준점에서는 곡선이 달라질 수 있다.
- 취소율은 모든 실행에서 0 이라 분석하지 못했다.
- 카드·IP 를 1로 고정했다. 실제 값을 넣으면 모든 계정의 점수가 올라가 차이가 줄어든다.
- 사용한 모델은 기존 스크립트를 그대로 다시 실행해 만든 사본이다 (`model_build/BUILD_RECORD.json`).
